# 디자인 계획: 중국 소재 공급망 경영진 보고 덱

## 0. 주제·청중·한 가지 일

- **주제**: 중국 반도체 소재 공급망의 차세대 메모리 대응 자립 가능성과 Choke Point
- **청중**: SK하이닉스 경영진. 결론부터 보고, 사실과 판단의 경계를 확인하며 읽는다.
- **덱의 한 가지 일**: 각 장에서 "무엇이 확인된 사실이고, 무엇이 당사 판단인가"를 3초 안에 구분하게 한다.
- **주제의 세계에서 가져올 어휘**: 웨이퍼 단면의 박막 적층(기판 위에 막이 증착된다), 공정 레이어 스택, 소재 → 팹으로 이어지는 공급 흐름. 장식이 아니라 정보 구조로만 쓴다.

## 1. 색상 토큰

기본 팔레트 (6개):

| 토큰 | hex | 역할 |
|---|---|---|
| `--paper` | `#F4F6F7` | 슬라이드 바탕. 실리콘 웨이퍼의 차가운 회백색 (크림 계열 회피) |
| `--ink` | `#14181D` | 헤드라인·사실 본문·표 텍스트 |
| `--muted` | `#5A6470` | 보조 텍스트, 축 라벨, 각주 |
| `--rule` | `#CDD3D9` | 표 구분선, 축, 레이어 경계 |
| `--film` | `#2B4A8B` | **당사 판단(View) 전용 색.** 코발트 계열. 판단 영역의 라벨·경계·마커에만 사용 |
| `--film-tint` | `#E5EBF4` | 판단 영역 바탕 (증착막) |

자립 단계 신호 (의미 색, 강조색과 별개. 5단계 고정):

| 키 | 라벨 | hex | 흑백 명도 순서 |
|---|---|---|---|
| `L3+` | L3 이상 | `#9FCDB2` | 가장 밝음 |
| `L2-3` | L2~L3 | `#EBCB5C` | 밝음 |
| `L2` | L2 | `#E08A3C` | 중간 |
| `L1-2` | L1~L2 | `#B9332B` (흰 글씨) | 어두움 |
| `EQ` | 장비 병목 | `#1E2228` (흰 글씨) | 가장 어두움 |
| `na` / `ok` | – / 보통 | 바탕색 + 점선 테두리 | – |

- 모든 신호는 색만으로 쓰지 않고 칩 안에 단계 텍스트(L1~L2 등)를 항상 쓴다. 색맹·흑백 인쇄에서는 텍스트가 1차 정보이고, 위험이 높을수록 어두워지는 명도 순서가 2차 정보다.
- 근거 등급 칩: `A` 채움(ink), `B` 외곽선(ink), `C` 점선 외곽선(muted). 색이 아니라 선의 형태로 구분해 흑백 인쇄에서도 남는다.

## 2. 서체와 역할

| 역할 | 서체 | 굵기 | 비고 |
|---|---|---|---|
| 헤드라인 | IBM Plex Sans KR | 600 | 기술 문서의 단단한 인상. 장식 없음 |
| 본문·표 | IBM Plex Sans KR | 400 / 500 | 표 안 숫자는 `tabular-nums` |
| 데이터·라벨 | IBM Plex Mono | 400 / 500 | 등급 칩, 배수, 점수, 축 눈금, 페이지 번호 |
| 중국어 간체 보충 | Noto Sans SC | 400 / 500 | Plex KR에 없는 간체자(龙·鑫·凯 등)만 담당 |

- 파일: `assets/fonts/`에 woff2 (Google Fonts에서 덱이 실제로 쓰는 글자만 서브셋으로 받음). jsDelivr가 막혀 Pretendard는 쓰지 않는다.
- 폴백 스택: `"IBM Plex Sans KR", "Noto Sans SC", Pretendard, "Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", sans-serif`
- `deck/build.py`가 slides.json의 글자 집합으로 서브셋을 다시 받는다. 문구를 바꿔 새 글자가 생겨도 폴백 스택으로 표시된다.

## 4. 핵심 시각 장치: 사실 = 기판, 판단 = 증착막

모든 본문 슬라이드(1~12)에서 같은 위치·같은 형태를 쓴다.

- **사실(Fact) 레이어**: 헤드라인 바로 아래. 바탕은 `--paper` 그대로, 왼쪽에 세로 라벨 "확인된 사실"과 ink 2px 실선. 각 항목 끝에 근거 등급 칩.
- **당사 판단(View) 레이어**: 슬라이드 하단. `--film-tint` 바탕 위에, 위쪽 경계에 `--film` 색의 6px 사선 해칭 띠(웨이퍼 단면에서 증착막을 그리는 관례)를 둔다. 왼쪽 세로 라벨 "당사 판단", 각 항목 끝에 "(분석 판단)".
- 흑백 인쇄에서도 해칭 띠와 라벨이 남아 구분된다.
- 도식 안에서 B 자료를 표시할 때도 같은 규칙을 쓴다: B 값은 `--film` 색 마커와 해칭, A 값은 ink.

### 대담한 장면: 8번 Heat Map

덱에서 유일하게 크게 쓰는 장면이다. 웨이퍼 단면처럼 읽히게 구성한다.
- 행을 소재군(리소그래피 / CMP·Wet / 증착·Target·Wafer·Gas / 패키징·본딩)으로 묶어 레이어처럼 쌓고, **장비 병목 3행을 맨 위에 짙은 캡 레이어로 올린다.** 헤드라인의 "그 위에 장비 병목"을 위치로 보여준다.
- 셀은 신호색으로 꽉 채우고 단계 텍스트를 쓴다. 4F²·HBM 두 열을 넓게, 3D DRAM·HBF(추정) 열은 좁게 두고 열 머리에 "추정" 표시.
- 맨 오른쪽 B 장비 의존 열은 판단 레이어 규칙(해칭 머리, film 색)을 따른다.
- 사실·판단 영역은 이 장에서만 한 줄로 줄인다(같은 위치·같은 형태는 유지).

Executive Summary(1번)는 조용하게 둔다.

## 6. 공통 요소

- 푸터: 왼쪽 "SK hynix 소재전략팀 | 대외비", 가운데 출처·등급 각주(15px, 최대 2줄), 오른쪽 페이지 번호(Mono, "03 / 15").
- 단계 신호를 쓰는 장에는 헤더 오른쪽 위에 5단계 범례를 같은 위치에 둔다.
- 부록(A1~A3)은 사실·판단 레이어 없이 표만 둔다. 헤드라인 크기는 동일.

## 7. 구현 방식

- `deck/index.html` 1개 파일. CSS·JS 인라인, 차트는 인라인 SVG와 HTML. 외부 라이브러리 없음.
- 콘텐츠: `deck/build.py`가 `content/slides.json`과 `content/verify.md`의 항목 수를 HTML 안의 `<script type="application/json">`에 넣는다. http로 열면 `../content/slides.json`을 직접 읽어 렌더링한다. 문구 수정 시 JSON만 고치고 `python3 deck/build.py`를 실행하면 된다.
- 중국 기업명 첫 등장 한자·영문 병기는 렌더러가 `{{키}}`를 슬라이드 순서대로 처리해 자동으로 한다.
- 키보드 ←/→, PageUp/PageDown, Home/End. 화면 크기에 맞춰 축소. URL 해시로 슬라이드 번호 유지.
- 인쇄 CSS: `@page { size: 1920px 1080px; margin: 0 }`, 슬라이드마다 한 페이지. 진입 애니메이션 없음.
